◉ GeoFind Smart Search

    FSD CIA 1 · Part 1 — Problem Definition and Innovation

    OpenStreetMap UX and Functionality Improvement Challenge

    Q1 · Benchmark Analysis

    Target users: Tourists, Travellers, Delivery Workers etc.

    Selected workflow: Searching for a location

    1. 01 Enter a search query
      The user types a place name, street or address.
    2. 02 View matching results
      The website displays possible matches for the query.
    3. 03 Identify the correct place
      The user compares names and available location details.
    4. 04 Select a result
      The selected location is displayed on the map.
    5. 05 Explore or plan a route
      The user inspects the area or uses the location as a destination.

    Existing features to benchmark: The existing OpenStreetMap website provides a location search field, search suggestions/results, map navigation and the ability to inspect a selected location.

    Problem Definition

    Improving Location Search Through Autocomplete

    Users may experience difficulties identifying the correct location when searching for places with similar names or multiple possible matches.

    Innovative Solution: Smart Location Search

    Develop a responsive search interface that displays relevant suggestions while users type and helps them distinguish between similar locations before selecting a result.

    The redesigned interface aims to:

    • Reduce the time needed to identify the correct location.
    • Reduce incorrect selections among similarly named places.
    • Make search easier for first-time users.

    1. Three meaningful JavaScript events

    EventWhere it is usedFunction
    inputSearch fieldFetch and display suggestions as the user types.
    submitSearch formValidate the query and search for the selected or entered location.
    clickSearch result cardSelect a location and display its details in the preview panel.

    2. User input form with validation and feedback

    The search form includes:

    • ✅ A location search field.
    • ✅ A clear-search button.
    • ✅ Validation for empty or excessively long queries.
    • ✅ A helpful message if the query is invalid.
    • ✅ A visible indication of the selected location.
    • ✅ A message if no matching location is found.

    3. Fetch API and JSON data handling

    Uses the Fetch API to retrieve real location data from OpenStreetMap's geocoding service, Nominatim.

    Autocomplete suggestions use a small local JSON dataset (js/data.js) so results appear instantly while typing. On submit, fetch() retrieves real matching locations.

    Loading, error and empty states

    The results area is never left blank. Click a state to preview it in the side panel.

    ⏳ Loading

    Spinner and “Searching for locations…”. Duplicate submissions are disabled.

    📭 Empty

    If the API returns an empty array: “No locations found. Try a different name or address.”

    ⚠️ Error

    “We couldn't load locations. Check your connection and try again.” with a Retry button.

    ✅ Success

    Matching location cards with contextual details. Selecting one highlights it and updates the preview.
